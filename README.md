# dicom-flow

A small, service-oriented DICOM pipeline demo. Step 1 implements a synthetic
ultrasound DICOM generator, a C-STORE receiver and a simple C-ECHO/C-STORE
sender. The receiver persists validated instances under
`StudyInstanceUID/SeriesInstanceUID/SOPInstanceUID.dcm`.

This project is a demo, not a medical device. Use only synthetic studies
generated by this project; do not send real patient data.

## Architecture

```text
Synthetic DICOM generator -> C-ECHO/C-STORE SCU -> DICOM C-STORE SCP -> disk
```

The receiver accepts ultrasound image storage from calling AE titles in its
comma-separated allow-list. Settings are read from `DICOM_FLOW_*` environment
variables or a local `.env` file. Receiver logs are JSON and intentionally
exclude DICOM attributes and patient identifiers.

## How to run

Requirements: Python 3.12 and `uv`, or Docker with Docker Compose.

### Local

```bash
uv sync
cp .env.example .env
uv run dicom-flow serve
```

In another terminal, generate and send a synthetic study:

```bash
uv run dicom-flow generate --output ./data/synthetic --instances 2 --seed 7
uv run dicom-flow send ./data/synthetic
```

### Docker Compose

```bash
docker compose up --build
```

From another terminal (with the project dependencies installed), generate and
send only synthetic test data:

```bash
uv run dicom-flow generate --output ./data/synthetic
uv run dicom-flow send ./data/synthetic
```

Received instances are stored in the Compose `received-data` volume. Set
`DICOM_FLOW_PORT`, `DICOM_FLOW_AE_TITLE`, and
`DICOM_FLOW_ALLOWED_CALLING_AE_TITLES` in the environment to configure the
receiver. Example values are in [.env.example](.env.example).

## Tests and checks

```bash
uv run pytest
uv run ruff check .
uv run mypy
```

The integration test starts a local receiver and sends a synthetic study over
DICOM. No external dataset is needed.
