# dicom-flow

A small, service-oriented DICOM pipeline demo. It generates synthetic
ultrasound studies, receives them over C-STORE, publishes instance events to
Redis Streams, runs deterministic mock inference, and writes JSON and HTML
reports per study.

This project is a demo, not a medical device. Use only synthetic studies
generated by this project; do not send real patient data.

## Architecture

```text
Synthetic DICOM -> C-STORE receiver -> Redis Stream -> worker
                                                -> JSON + HTML report
```

The receiver stores validated instances under
`StudyInstanceUID/SeriesInstanceUID/SOPInstanceUID.dcm` and publishes their
study, series, and instance UIDs to Redis after each successful store. The
worker uses a Redis consumer group, acknowledges successful processing, retries
failures up to a configurable limit, and places exhausted messages on a
dead-letter stream. The deterministic mock detector and classifier use the
versioned [inference config](src/dicom_flow/inference/mock_inference.yaml);
each JSON result includes its SHA-256 config hash. Reports state that they are
not for clinical use.

The receiver accepts ultrasound image storage only from calling AE titles in
its comma-separated allow-list. Settings are read from `DICOM_FLOW_*`
environment variables or a local `.env` file. Receiver logs are JSON and omit
DICOM attributes and patient identifiers.

## How to run

Requirements: Python 3.12 and `uv`, or Docker with Docker Compose.

### Docker Compose

Compose starts Redis, receiver, and worker:

```bash
docker compose up --build
```

In another terminal, with the project dependencies installed:

```bash
uv sync
uv run dicom-flow generate --output ./data/synthetic --instances 2 --seed 7
uv run dicom-flow send ./data/synthetic
```

Reports are written to the Compose `report-data` volume under
`StudyInstanceUID/result.json` and `StudyInstanceUID/report.html`. The receiver
stores DICOM files in the `received-data` volume.

### Local services

Start Redis with Compose:

```bash
docker compose up --detach redis
cp .env.example .env
uv run dicom-flow serve
```

In another terminal:

```bash
uv run dicom-flow generate --output ./data/synthetic
uv run dicom-flow send ./data/synthetic
```

Run a local worker separately with `uv run dicom-flow worker`. Configure the
receiver, Redis stream/group, worker retries, and output directories through
environment variables; see [.env.example](.env.example).

## Tests and checks

Start Redis before running the full suite so Redis integration and end-to-end
tests run rather than skip:

```bash
docker compose up --detach redis
uv run pytest
uv run ruff check .
uv run mypy
```

Tests generate all DICOM input synthetically; no external dataset is needed.
