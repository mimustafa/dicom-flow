# Next-step handoff

Use this page as the starting point for the next development session. The
current project is a synthetic-data-only portfolio demo, not a medical device.
Do not introduce real patient data or imply clinical suitability.

## Current baseline

- Implemented: synthetic ultrasound generation, C-STORE receiver and
  UID-organized storage, Redis Streams events, mock inference, JSON/HTML
  reporting, Secondary Capture forwarding, Orthanc Compose destination,
  optional outbound TLS, health checks, CI, and lightweight traceability docs.
- Verified at the end of Step 3: Ruff, strict mypy, Docker build, Compose
  services, and tests with a 70% coverage gate. Run the checks again after
  changes; do not treat this note as proof of the current checkout's status.
- Main constraints and residual behavior are recorded in
  [architecture.md](architecture.md), [risk-analysis.md](risk-analysis.md),
  and [README.md](../README.md).

## Start/check procedure

1. Read this page, then inspect current behavior in the named files and tests;
   this plan can become stale as the project changes.
2. Select one candidate or update the table to reflect a different agreed
   scope. Avoid combining independent reliability and security changes.
3. Use only DICOM generated by `dicom_flow.synthetic` or test fixtures derived
   from it. Never download or add patient data.
4. Run `uv run pytest`, `uv run ruff check .`, `uv run mypy`, and
   `docker compose up --build`; record actual results in the verification
   template at [verification-report-template.md](verification-report-template.md).
5. Update [requirements-traceability.md](requirements-traceability.md),
   [risk-analysis.md](risk-analysis.md), and [CHANGELOG.md](../CHANGELOG.md)
   when the selected change affects requirements, hazards, or delivered
   behavior.
